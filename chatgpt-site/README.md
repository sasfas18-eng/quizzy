# كويزي داخل ChatGPT

هذا مصدر Site مع MCP وواجهة مضمّنة في ChatGPT. افتح التطبيق بأداة `open_quizzy` أو بقول «افتح كويزي» بعد تثبيت إضافة الموقع. يرفع الطالب PDF/PPTX داخل الواجهة المضمّنة ويضغط «إنشاء الكويز»؛ يقرأ المتصفح الصفحات نصيًا ويحفظ المختار في R2 تحت معرّف الطالب الذي توفره Sites، ثم ترسل الواجهة طلب التوليد إلى نموذج المحادثة تلقائيًا بواسطة `sendFollowUpMessage`. لا ينسخ الطالب الملف أو النص أو الطلب بين الموقع والمحادثة، ولا يوجد مفتاح API في الكود.

رابط Site الخارجي يعرض الكويزات المحفوظة وحلها، ويوجه إنشاء كويز جديد إلى الواجهة المضمّنة في ChatGPT. لا يملك الرابط الخارجي اتصالًا بحصة ChatGPT وحده؛ يجب أن تكون إضافة كويزي متاحة ومثبتة في حساب الطالب. إتاحة الإضافة للزائرين وتوليد الكويز فعليًا من حساب طالب آخر يحتاجان تحققًا بحساب ثانٍ؛ نجاح اختبارات الواجهة المحلية لا يثبت ذلك.

توجد قواعد المصدر والكتابة المرجعية في `knowledge/lecture_reader.py` و`knowledge/quiz_engine.py`. يعيد `get_source` هذه القواعد باختصار مع المصدر للنموذج. يتحقق الخادم من الاقتباس والصفحة، ويمنع الأسئلة عن بيانات المحاضر والأهداف والمراجع، ويفحص تكرار الغرض والنص، ويرتب الخيارات بحيث تتوازن حروف الإجابات. التحقق الآلي لا يثبت الصحة العلمية أو وجود مراجعة بشرية.

اختبر: `npm test && npm run build && npm run check:artifact`. المعاينة المحلية: `node scripts/preview.mjs --demo`. المصدر المرفوع يُحفظ كنص الصفحات المختارة، وليس نسخة ثنائية من PDF/PPTX. الصفحات المصورة أو غير المقروءة لا تدخل التوليد؛ التطبيق يبين أرقامها. استخدام الطلاب مرتبط بإتاحة إضافة Site لكل زائر وتسجيلهم في ChatGPT وحدود خططهم.
