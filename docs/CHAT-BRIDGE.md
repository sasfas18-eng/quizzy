# إنشاء الأسئلة عبر الحسابات الخارجية: الحالة الفعلية

**آخر تحقق: 4 نوفمبر 2026.** طلب المنتج هو أن يربط الطالب حسابه مرة واحدة في ChatGPT أو Claude، ثم يولّد «كويزي» الأسئلة تلقائيًا داخل الموقع وعلى حصة ذلك الحساب، دون تكلفة على صاحب الموقع. **هذا الطلب غير منفّذ في موقع GitHub Pages الحالي.** لا تعرض واجهة النسخة الحالية تسجيل دخول لدى أي من الخدمتين داخل «كويزي»؛ خيار المحادثة مجرد نقل يدوي للطلب والرد. التوليد المحلي من الملف تلقائي ويعمل بلا حساب، لكنه ينتج أسئلة أبسط.

## ما يعمل الآن

1. يرفع الطالب PDF/PPTX ويحدد النطاق والإعدادات.
2. يستطيع إنشاء كويز محلي تلقائيًا، أو اختيار نقل يدوي إلى ChatGPT أو Claude.
3. في النقل اليدوي ينسخ طلبًا من كويزي، ويلصقه في حسابه لدى الخدمة المختارة، ثم يعيد JSON إلى كويزي.
4. يفحص كويزي البنية والمصدر والمفتاح والتكرار قبل اعتماد بنك الأسئلة. الاستيراد الذري يبقي البنك السابق إذا لم ينجح التحقق.

لا يرسل الموقع الملف إلى ChatGPT أو Claude تلقائيًا ولا يقرأ جلسة أي منهما. لا يحتاج الطالب حسابًا في الخدمتين معًا. لا يُدّعى لهذا المسار حل أعمى مستقل أو مراجعة بشرية؛ يسجل `blind_solver: false` و`external_chat: true`.

## ما يلزم للربط التلقائي الذي طلبه صاحب المشروع

**ChatGPT:** لدى OpenAI الآن «Sign in with ChatGPT» مع صلاحية اختيارية لاستخدام حصة خطة ChatGPT في طلبات Responses API. [دليل التطبيقات المفتوحة والمحلية](https://developers.openai.com/siwc/token-sharing-open-source) يخص التطبيقات المفتوحة المصدر أو المستضافة محليًا، ويطلب مسار OAuth بنقطة رجوع محلية `127.0.0.1`؛ لا ينطبق تلقائيًا على موقع كويزي المستضاف عن بُعد على GitHub Pages. [دليل المواقع](https://developers.openai.com/siwc/website) و[طلب معرّف العميل](https://developers.openai.com/siwc/request-client-id) يذكران أن مواقع الشركاء التجاريين تحتاج قبولًا ومعرّف OAuth وعنوان رجوع مسجلًا وخلفية آمنة لتبادل الرموز والتحقق منها. يحتاج «كويزي» إلى قبول المزود وتهيئة خلفية قبل تشغيل الربط للطلاب؛ نشر ملفات Pages وحدها لا يحقق ذلك. تتغير أهلية استخدام الحصة بحسب نوع الخطة وشروط البرنامج، ولا يمكن الوعد بأن كل حساب مجاني سيموّل التوليد تلقائيًا. [شرح OpenAI للأهلية](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites).

**Claude:** [سياسة Anthropic الرسمية للحسابات والأدوات الخارجية](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account) توجه التطبيقات الخارجية إلى Claude Console API key أو مزود سحابي مدعوم، وتحظر توجيه استخدام أداة خارجية إلى حدود اشتراك Claude الشخصي. لذلك لا يوجد مسار مدعوم حاليًا لزر «اربط Claude» في موقع كويزي ثم توليد تلقائي من حصة Free/Pro/Max الشخصية. واجهة Claude API مستقلة في الفوترة عن اشتراك المحادثة [بحسب دعم Anthropic](https://support.claude.com/en/articles/9876003-why-is-claude-api-usage-billed-separately-from-my-paid-claude-plan).

**الخطوة الخارجية اللازمة قبل تنفيذ ChatGPT:** تقديم كويزي إلى [نموذج اهتمام Sign in with ChatGPT](https://openai.com/form/sign-in-with-chatgpt-interest/)، ثم الحصول على معرّف عميل وصلاحية استعمال الحصة وشروط الإطلاق. بعد ذلك ننفذ OAuth على خلفية آمنة، ونخزن رمز كل طالب معزولًا عن غيره، ونربط إنشاء الكويز بطلبات Responses API ونختبر حسابين وحدود الحصة والتراجع. لا تُوضع رموز الطلاب في كود Pages أو في رابط URL. لا يُضاف زر ربط فعلي قبل توافر البرنامج ونجاح اختبار تكامل حي.

## التحقق الحالي من النقل اليدوي

يغطي `static-edition/test/run_web_chat_bridge.js` إعداد الطلب، وروابط الخدمتين، ورفض الرد غير الكافي دون تغيير الكويز، وقبول بنك صالح مع اقتباس المصدر ومفتاح الإجابة. يعمل الاختبار بمحاكاة الرد، بلا اتصال حي بالخدمتين؛ لذلك **لا يثبت ربط الحساب أو التوليد التلقائي لديهما**.
