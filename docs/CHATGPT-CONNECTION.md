# ربط ChatGPT التلقائي: الكود والحد التشغيلي

**حالة 4 نوفمبر 2026:** أضيف مسار OAuth وخط توليد ChatGPT Plan إلى **نسخة خادم FastAPI** في هذا المستودع. لا يوجد معرّف عميل OpenAI أو خادم عام موصول في الإعدادات الحالية، ولذلك **لم يعمل الربط مع حساب حقيقي ولم يُفعّل على موقع GitHub Pages**. لا يظهر زر ربط وهمي في Pages. هذا الملف يصف ما يمكن مراجعته في الكود وما يلزم لإطلاقه، دون ادعاء أن خدمة OpenAI وافقت على كويزي.

## رحلة الطالب عندما يصبح الخادم جاهزًا

1. يسجّل الطالب دخوله إلى حساب كويزي العادي؛ حسابه الدراسي مستقل عن ChatGPT.
2. من «حسابي» يضغط «اربط حساب ChatGPT»، فينتقل إلى صفحة موافقة OpenAI الرسمية.
3. يعود إلى كويزي عبر `/api/chatgpt/callback`. يتحقق الخادم من `state` وPKCE والجلسة وID token وصلاحية `chatgpt.tokens.use.direct`. الرموز تحفظ مشفّرة ومربوطة بمعرف طالب كويزي.
4. يصبح «إنشاء عبر ChatGPT» هو الفعل التلقائي عند فتح كويز جديد. يقرأ الخادم صفحات الملف ويختار نموذجًا متاحًا للحساب من `/v1/models`، ثم يستخدم Responses API مع `store:false` و`stream:true`، ويحفظ الأسئلة المقبولة عبر مسار التدقيق الموجود.
5. يمكن للطالب فصل الحساب. يحاول الخادم إلغاء رمز التجديد لدى OpenAI ويمحو الربط المحلي. إذا تعذر التأكد من الإلغاء البعيد تظهر ملاحظة لمراجعته في إعدادات ChatGPT.

الملفات الأساسية: `backend/app/routers/chatgpt.py`، `backend/app/services/chatgpt_oauth.py`، `backend/app/services/chatgpt_plan.py`، `backend/app/routers/quizzes.py`، `frontend/js/main.js`، `frontend/js/pages_quiz.js`. اختبار العقد والعزل في `backend/tests/test_chatgpt_connection.py` يستخدم محاكاة مزود؛ **لا يثبت قبول OpenAI أو نجاح طلب حي**.

## متطلبات التفعيل الخارجية

1. [قدّم كويزي لبرنامج Sign in with ChatGPT](https://openai.com/form/sign-in-with-chatgpt-interest/) بوصفه موقعًا مستضافًا عن بُعد، واحصل على موافقة استخدام الحصة ومعرّف عميل. [دليل المواقع](https://developers.openai.com/siwc/website) يطلب OAuth client وعنوان رجوع دقيقًا وخادمًا. مسار التسجيل الديناميكي المفتوح للأدوات المحلية له عنوان رجوع `127.0.0.1`، فلا يصلح تطبيقه بصمت على GitHub Pages.
2. انشر خادم FastAPI على HTTPS مع قاعدة/قرص دائم، ثم سجّل `https://<عنوان-الخادم>/api/chatgpt/callback` لدى OpenAI. اضبط `QUIZZY_PUBLIC_URL` على أصل الخادم نفسه، و`QUIZZY_COOKIE_SECURE=1`، و`QUIZZY_SECRET` عشوائيًا ثابتًا لا يقل عن 32 حرفًا. ضياع السر يمنع فك رموز الطلاب؛ ضياع قاعدة البيانات يفقد الربط والمحاولات.
3. اضبط `QUIZZY_CHATGPT_CLIENT_ID`. اضبط `QUIZZY_CHATGPT_CLIENT_SECRET` فقط إذا خصص OpenAI للعميل طريقة `client_secret_basic`؛ العملاء العامون لا يملكون سرًا. راجع الصلاحيات والنموذج الممنوحين في موافقة الشراكة؛ المتغيران `QUIZZY_CHATGPT_SCOPES` و`QUIZZY_CHATGPT_MODEL` قابلان للضبط.
4. اختبر حسابين حقيقيين منفصلين، وإتمام الكويز، وحد الحصة، وتجديد الرموز، والإلغاء، قبل إظهار زر الربط على الموقع العام. هذا التحقق **لم يحدث** لغياب الاعتماد والاستضافة.

موقع `https://sasfas18-eng.github.io/quizzy/` ثابت ولا يستطيع تنفيذ رد OAuth أو تخزين الرموز بأمان. لن يظهر فيه مسار الخادم تلقائيًا بمجرد دفع الكود إلى GitHub. يحتاج قرار نشر مستقل يضع واجهة كويزي وخادمه على أصل واحد، أو بنية خلفية موثوقة مكافئة؛ لا تضع رموز الطلاب في `config.js` أو `localStorage`.

وفق [شرح OpenAI للأهلية](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)، استخدام حصة ChatGPT في المواقع التجارية المشاركة متاح لخطط Go وPlus وPro، وليس لحساب Free. حساب الطالب هو الذي يتحمل حد الاستخدام؛ ربط الحساب لا يزيل حدود الخطة ولا يضمن 15 ثانية لكل كويز.
