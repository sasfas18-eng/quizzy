# نسخة GitHub Pages (الويب) — حسابات حقيقية وتوليد حقيقي بلا خادم

## الرابط والنشر: GitHub وحده
- **النشر تلقائي من GitHub:** كل تعديل يُدفع إلى المستودع (فرع `main` أو `claude/**`) يُختبر كاملًا في `ci.yml`، فإن نجحت كل الاختبارات نشرته مهمة `deploy` على فرع `gh-pages` فيتحدث الموقع خلال دقيقة أو دقيقتين. لا خطوة يدوية ولا رابط آخر؛ نسخة claude.ai (artifact) لم تعد تُحدَّث.
- **لا يخلط المتصفح بين إصدارين:** GitHub Pages يترك المتصفح يحتفظ بالملفات ١٠ دقائق، فبعد نشرتين متتاليتين قد يعمل html جديد مع سكربتات قديمة. لذلك يختم `scripts/stamp_site.py` (آخر خطوة في النشر) كل رابط سكربت/تنسيق/وحدة بـ `?v=<بصمة المحتوى>`: إصدار جديد = روابط جديدة. وإن رأيت صفحة غريبة بعد نشر جديد فحدّث بـ Ctrl+Shift+R.
- **أي إصدار منشور الآن؟** افتح `<رابط الموقع>/version.json` فيظهر رقم الإيداع ووقت البناء، وتطابقه مع آخر إيداع في GitHub.
- **أمر طارئ بلا انتظار الاختبارات:** `bash scripts/deploy_pages.sh` (الأمر نفسه تشغّله المهمة).
- **ذكاء Chrome المدمج: لا يحتاج أي رمز.** واجهة Prompt API صارت ثابتة على المواقع منذ Chrome 148 (مايو ٢٠٢٦)، فلا يلزم «رمز تجربة» ولا متغير `QZ_CHROME_AI_TOKEN` (يبقى المتغير مقبولًا فقط لتجربة مستقبلية من Chrome إن احتجنا لها).
- **الرابط الحالي:** **https://sasfas18-eng.github.io/quizzy/** (المستودع اسمه `quizzy`؛ الرابط = `https://<المستخدم>.github.io/<اسم المستودع>/`). صفحة المشغل: `…/quizzy/#/operator`.
  - بياناتك المحفوظة (الملفات، الكويزات، وضع المشغل) **باقية**، لأن المتصفح يحفظها بحسب الدومين `sasfas18-eng.github.io` لا بحسب المسار.
  - الرابط القديم (باسم المستودع الطويل) توقف لأن GitHub لا يحوّل روابط Pages؛ أما روابط المستودع نفسها فتحوّل تلقائيًا.
- **أفضل اسم: دومين خاص** (مثل `quizzy.example.com`): **Settings ← Pages ← Custom domain**. تنبيه: المتصفح لا ينقل بياناته المحفوظة من دومين إلى آخر، فصدّر بياناتك من صفحة «حسابي» قبل الانتقال.

GitHub Pages تستضيف ملفات ثابتة فقط، فالنسخة هنا **تعمل كلها في متصفح الطالب** وتستعين بخدمتين مجانيتين للجزأين اللذين يحتاجان شبكة:

| الجزء | كيف | يحتاج |
|---|---|---|
| **توليد الأسئلة** | **بلا مفتاح يعمل تلقائيًا توليد محلي أبسط** (من نص الملف على جهاز الزائر بلا أي طلب شبكة). وللأعمق: الصفحة تستدعي مزوّد الذكاء الاصطناعي مباشرة من المتصفح (Gemini/Groq/OpenRouter مجانًا بحدود، أو Anthropic، أو Ollama محليًا). مجمّع يوزّع الطلبات ويبطّئ تحت الحد وينتقل لمزوّد آخر عند 429. النموذج يُختار تلقائيًا مما يسمح به المفتاح | **إما** مزوّد الموقع في `config.js` (الزائر لا يحتاج شيئًا — انظر «تفعيل التوليد لكل الزوار»)، **أو** مفتاح من الزائر يلصقه مرة واحدة (بطاقة «اربط الذكاء الاصطناعي») |
| **الحسابات والحفظ** | Supabase: بريد وكلمة مرور وروابط تأكيد/استعادة، وقاعدة بيانات تعزل كل طالب عن غيره (Row Level Security) | مشروع Supabase مجاني **يُنشئه صاحب الموقع مرة واحدة** (٣ دقائق) |
| **PDF** | صفحة طباعة (`#/print/…`) ← «حفظ كـ PDF» من المتصفح (عربي سليم) | لا شيء |

بدون إعداد Supabase يعمل الموقع في **وضع الجهاز**: كل شيء يُحفظ في متصفح الطالب فقط (لا حسابات سحابية ولا انتقال بين الأجهزة)، لكنّ الموقع **يطلب بريدًا وكلمة مرور** كأي موقع بحسابات: حساب حقيقي بمساحته الخاصة على هذا الجهاز (تُحفظ تجزئة كلمة المرور لا الكلمة، ولا استعادة لكلمة المرور بلا خادم بريد، وأول حساب يتبنّى ما كان محفوظًا على الجهاز). و«الدخول كضيف» مساحة **منفصلة** مؤقتة لا ترى ملفات الحساب. **لحسابات سحابية تنتقل بين الأجهزة وتُستعاد كلمة مرورها فعّل Supabase** بالخطوات أدناه (النماذج نفسها تعمل ضد السحابة).

**الملفات المصوّرة (الممسوحة ضوئيًا)** تُقرأ داخل متصفح الطالب بـ tesseract.js. ملفاتها (≈١٦ م.ب) لا تُحفظ في المستودع: خطوة النشر في الـCI تجلبها (`scripts/fetch_ocr.sh`، إصدارات مثبّتة ومتحقَّق من بصمتها). إن نشرت يدويًا فشغّل `bash scripts/fetch_ocr.sh` قبل `bash scripts/deploy_pages.sh`؛ وبدونها يعمل الموقع ويرفض الملف المصوّر بصدق.

## إعداد الحسابات (مرة واحدة، لصاحب الموقع)
1. ادخل إلى https://supabase.com ← **Start your project** ← سجّل (يمكنك بحساب GitHub) ← **New project**: اختر اسمًا وكلمة مرور لقاعدة البيانات ومنطقة قريبة ← انتظر دقيقتين.
2. **SQL Editor ← New query**: الصق محتوى `supabase/schema.sql` كاملًا ← **Run**. (آمن للتكرار.)
3. **Authentication ← URL Configuration**: ضع في **Site URL** رابط موقعك على Pages (مثل `https://<user>.github.io/<repo>/`) وأضفه إلى **Redirect URLs**. بدون هذا تشير روابط البريد إلى عنوان خاطئ.
4. **Authentication ← Providers ← Email**: اتركه مفعّلًا. اختر بين:
   - إيقاف **Confirm email**: تسجيل فوري (مناسب لفصل صغير)، أو
   - إبقاؤه مفعّلًا وإعداد SMTP خاص (Authentication ← SMTP). **تنبيه:** بريد Supabase المدمج محدود جدًا بالساعة، فلا يكفي لفصل كامل دون SMTP.
5. **Project Settings ← API**: انسخ **Project URL** و**anon public key** (كلاهما عام بطبيعته؛ الأمان من سياسات قاعدة البيانات لا من إخفائهما). لا تنسخ `service_role` أبدًا.
6. **ضع القيمتين كمتغيّرين في GitHub** (الطريقة المفضّلة: لا تعديل ملفات): في مستودع الموقع **Settings ← Secrets and variables ← Actions ← Variables ← New repository variable**، أضف متغيّرين (Variables لا Secrets، فهما عامّان):
   - `QZ_SUPABASE_URL` = الـProject URL (مثل `https://abcd.supabase.co`)
   - `QZ_SUPABASE_ANON_KEY` = الـanon public key (يبدأ بـ`eyJ` أو `sb_publishable_`)

   ثم **Actions ← آخر تشغيل لـ ci ← Re-run all jobs** (أو أي دفعة جديدة): تنشر خطوة النشر القيمتين في `config.js` تلقائيًا، فيتحدّث الموقع خلال دقيقة أو دقيقتين. **أمان**: يرفض النشر أي مفتاح `service_role` أو `sb_secret_` (السرّي الذي يعطي كل زائر قاعدة بياناتك) ولا يطبعه، ولو وُضع يدويًا في `config.js` أوقف المتصفح الحسابات وأخبرك. (طريقة بديلة: تعديل `config.js` في فرع `gh-pages` يدويًا بـ`window.QZ_CONFIG = { supabaseUrl: '…', supabaseAnonKey: '…' };`، أو أرسل لي القيمتين العامّتين وأنا أضعهما.)
7. **تحقّق**: افتح `#/operator` على موقعك (تفعيل وضع المشغّل على جهازك) ← بطاقة **«الحسابات السحابية»** ← **«افحص الحسابات»**: تتأكد من أن المشروع يستجيب والمفتاح مقبول والتسجيل بالبريد مفتوح وجدول البيانات ودالة حذف الحساب موجودان، وتقول لك ما يُصلَح إن وُجد خلل. بعدها سجّل حسابًا بالبريد من الصفحة الرئيسية وجرّب.

> ما كان محفوظًا في **وضع الجهاز** (قبل التفعيل) يبقى على ذلك المتصفح ولا ينتقل إلى الحسابات الجديدة؛ ملفات كل طالب بعد التفعيل في حسابه السحابي.

## التوليد
كل الكويزات والبطاقات تُنشأ **محليًا في متصفح الطالب** (المولّد المحلي + وكيل الصياغة + الفحص الذاتي)، بلا أي خدمة ذكاء اصطناعي، ولا مفتاح، ولا تكلفة. لا يوجد في الموقع أي حقل لمفتاح.

**ذكاء وكيل الصياغة في كل المتصفحات (مجاني، تلقائي):** يحمل الموقع نفسه نموذجًا مفتوحًا صغيرًا (all-MiniLM-L6-v2 مع transformers.js، نحو ٤٥ ميغابايت) يعمل داخل متصفح الطالب بـ WebAssembly — Safari وFirefox وChrome والجوال — بلا مفتاح ولا خادم، ولا يخرج شيء من الجهاز. يُنزَّل مرة واحدة مع أول كويز (لا يُنزَّل على اتصال «توفير البيانات») ثم يبقى في المتصفح. يقرأ المعنى: سؤالان يسألان المعلومة نفسها بكلمات مختلفة، أو خيار خاطئ بمعنى الإجابة الصحيحة ← يعيد وكيل الصياغة كتابتهما. ملفاته يجلبها النشر (`scripts/fetch_semantic.sh`) ولا تُحفظ في المستودع؛ صفحة المشغل فيها بطاقة بحالته وزر «جرّب الآن».

**ذكاء Chrome المدمج لوكيل الصياغة (مجاني، تلقائي، بلا رمز):** إذا كان الطالب على Chrome 148 أو أحدث على الحاسوب (ويندوز وماك ولينكس) وجهازه يستوفي متطلبات Google (مساحة فارغة ٢٢GB، ومعالج رسوميات بذاكرة أكثر من ٤GB أو ذاكرة ١٦GB وأربع أنوية)، يفحص به وكيل الصياغة كل سؤال ويحسّن صياغة الأسئلة الإنجليزية خلال ١٠ ثوانٍ، وكل ما يقترحه يُتحقق منه مقابل نص المحاضرة. واجهة Prompt API ثابتة على المواقع منذ Chrome 148 فلا يلزم أي رمز. الجوال وSafari وFirefox لا يوفّرونه — يعمل فيها النموذج المفتوح أعلاه. حالته على جهازك في صفحة المشغل (`#/operator`).

## ما الذي يضمنه ما بُني (واختُبر)
- `supabase/test/rls.test.mjs`: على **PostgreSQL حقيقي** — كل طالب يرى صفوفه فقط، لا يستطيع كتابة صفوف باسم غيره ولا نقل ملكيتها، مفتاح `anon` وحده لا يرى شيئًا، وحذف الحساب يمحو بياناته فقط.
- `static-edition/test/run_web_supabase.js`: متصفح Chromium حقيقي مع خادم Supabase وهمي: تسجيل، حفظ، استعادة الجلسة بعد إعادة التحميل، عزل بين طالبين، تغيير كلمة المرور، رابط الاستعادة، رابط تأكيد البريد، حذف الحساب.
- `static-edition/test/run_web_local.js`: بطاقة «اربط الذكاء الاصطناعي» بمفتاح يلصقه الزائر (اكتشاف النموذج تلقائيًا من المزوّد)، ثم **نقرة واحدة ← كويز جاهز**، تحقق مجمّع، تعامل مع 429، طباعة PDF، تصدير ومسح البيانات — كله عبر HTTP حقيقي مع خادم محاكى متوافق مع OpenAI.
- `static-edition/test/run_web_realistic.js`: **بلا أي إعداد من الزائر** (مزوّد الموقع من `config.js`): ملفات PPTX/PDF واقعية ← أسئلة، ونموذج يُفسد صيغة التحليل، وملف شبه فارغ يشرح الموقع لماذا لا يكفي ويعرض طريقًا للمتابعة.
- **لم يُختبر** مقابل Supabase الحقيقي ولا مزوّدي الذكاء الحقيقيين (لا حسابات لدي)، ولا يُعرف سلفًا أيّ المزوّدين يسمح بطلبات المتصفح (CORS): زر «اختبار» في الإعدادات يكشف ذلك.

## حدود النسخة
- المفتاح محفوظ في متصفح الطالب (نص). استخدموا مفاتيح مجانية/محدودة، لا مفاتيح ذات رصيد كبير.
- لا لوحة إدارة ولا بلاغات للمشرف (البلاغات تُحفظ عند صاحبها فقط).
- التوليد يعمل ما دامت الصفحة مفتوحة.
