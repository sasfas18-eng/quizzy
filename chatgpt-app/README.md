# كويزي داخل ChatGPT — نسخة خاصة قابلة للتجربة

**تحديث 5 نوفمبر 2026 — الرجوع إلى تجربة ChatGPT الأصلية:** فُحص مصدر Site الأقدم «كويزي — معاينة التصميم» (`quizzi-study-design`). ملفه `README.md` وراية `DESIGN_PREVIEW` يثبتان أنه معاينة ثابتة لا تستقبل ملفات أو حسابات ولا تستدعي نموذجًا؛ لا تُعدّ دليلًا على توليد مباشر من صفحة الويب. المسار الفعلي الذي يستخدم نموذج ChatGPT دون مفتاح API هو واجهة تطبيق كويزي المضمّنة داخل `chatgpt.com`. بعد إرسال طلب الملف من واجهتها، تراقب الآن قائمة الكويزات المحفوظة وتفتح الكويز الجديد تلقائيًا **بعد تأكيد حفظه من أداة الخادم**؛ إذا لم يثبت الحفظ خلال دقيقتين تعرض حالة فشل واضحة. هذا التحسين لا يجعل صفحة `chatgpt.site` الخارجية قادرة على استدعاء النموذج.

**تحديث 5 نوفمبر 2026:** أضيفت في رابط `chatgpt.site` صفحة رفع PDF/PPTX واختيار الصفحات والإعدادات. تستخرج الصفحة النص المقروء وتحفظه في R2 بمعرّف طالب ChatGPT، ثم تفتح طلبًا جاهزًا في `chatgpt.com`. تقرأ أداة `get_source_for_generation` المصدر المحفوظ للحساب نفسه؛ يولّد نموذج المحادثة الأسئلة ويستدعي `create_quiz_from_slides` مع `source_id`، فيفحص الخادم الدليل مقابل النص المخزن قبل الحفظ. يمكن العودة إلى الصفحة لحل الكويز ومراجعة الإجابات، واستئناف مصدر ينتظر التوليد أو حذفه. **الموقع المستقل لا يشغّل نموذج ChatGPT داخل صفحته؛ يتطلب اكتمال التوليد اتصال تطبيق كويزي بحساب الطالب وموافقة/إرسال الطلب في ChatGPT.** لا تُعرض أسئلة محلية على أنها من ChatGPT. التطبيق والموقع الخاص ما زالا متاحين للمالك وحده؛ لم يُثبت توزيع الإضافة لطلاب آخرين.

هذا تطبيق منفصل داخل ChatGPT مبني على Sites MCP. يرفع الطالب ملف PDF أو PPTX في المحادثة، ويقرأه نموذج ChatGPT المتاح لحسابه، ويُعدّ نص الصفحات والأسئلة. أدوات كويزي تحفظ الأسئلة والإجابات وتعرضها لاحقًا. لا يستدعي كود التطبيق OpenAI API ولا يحتاج مفتاحًا من مالك كويزي. **هذه الآلية داخل ChatGPT فقط**؛ لا تفعّل التوليد بنموذج ChatGPT في موقع GitHub Pages المستقل.

**تصحيح النطاق:** يريد صاحب المشروع توليدًا من نموذج ChatGPT دون مفتاح API، مع رفع الملف من واجهة كويزي. أضيف مساران: واجهة مضمّنة داخل chatgpt.com ترسل الطلب مباشرة إلى محادثة المضيف، وصفحة `chatgpt.site` تحفظ المصدر وتفتح طلب التوليد في المحادثة. الثاني يحتاج الانتقال إلى ChatGPT لأن تسجيل الدخول إلى Site وحده لا يمنحه صلاحية استدعاء النموذج. مسار [CHATGPT-CONNECTION.md](../docs/CHATGPT-CONNECTION.md) يخص موقعًا مستقلًا يستخدم حصة ChatGPT عبر موافقة OAuth، وهو خيار تقني مختلف.

**واجهة التطبيق المضمّنة (قيد التحقق الحي):** أضيفت أداة `open_quizzy` وموارد MCP Apps لعرض نموذج رفع PDF/PPTX وإعداد الكويز وقائمة المحفوظات والحل والمراجعة داخل chatgpt.com. يقرأ المتصفح نص الصفحات محليًا، ثم يستخدم `sendFollowUpMessage` لإرسال المصدر والطلب إلى نموذج المحادثة، ويُطلب من النموذج حفظ الأسئلة بأدوات كويزي. هذا لا يحتاج مفتاح API من الطالب أو المالك، لكنه ينتج رسالة داخل المحادثة ولا يضمن أن النموذج سيكمل جميع الدفعات. نجح فحص المورد والأداة واختبار إرسال صفحة PDF مختارة دون الغلاف بمحاكاة مضيف؛ **نجاح رفع ملف حقيقي من الواجهة وتوليد كويز وعرضه داخل ChatGPT لم يُثبت بعد**. المكتبات النصية للملفات تُحمَّل من أصول كويزي العامة في GitHub Pages، لذا يتطلب هذا المسار اتصالًا بها. الصفحات المصورة/غير المقروءة لا تدخل المصدر، وملفات أطول من 100 صفحة أو مصدر يتجاوز 30 ألف حرف تحتاج تضييق النطاق.

الرابط الخاص الحالي: <https://quizzy-chatgpt-study.sasfas18.chatgpt.site>. التطبيق مملوك لصاحب المشروع ومثبت له حاليًا؛ إتاحته للطلاب من حساباتهم تتطلب نشرًا/مراجعة وتوزيعًا مناسبًا للتطبيق، ولا يكفي نشر الرابط وحده.

## المسار المنفذ

1. يرفع الطالب ملفه داخل محادثة ChatGPT ويطلب كويزًا باستخدام تطبيق كويزي.
2. يستخرج النموذج النص المقروء مع أرقام الصفحات، ثم يرسل دفعة أسئلة إلى `create_quiz_from_slides`. للعدد الكبير تُستخدم `add_quiz_questions` حتى 100 سؤال، على دفعات لا تتجاوز 30.
3. تفحص الأداة شكل الأسئلة، تطابق اقتباس الدليل مع نص الصفحة المرسل، تفرد الخيارات والمفتاح، وتكرار نص السؤال والغرض. لا تُفرض الهوية العشرة إذا لم يدعمها المصدر؛ تعاد الأقسام الناقصة صراحةً.
4. تحفظ البيانات في R2 ضمن مفتاح مبني على معرّف مستخدم ChatGPT الذي تقدمه Sites. أدوات MCP تعرض الكويزات والأسئلة، تحفظ الإجابات، وتراجع الأخطاء. التدريب يصحح فورًا، والاختبار يحجب المفتاح حتى اكتمال الإجابات.
5. الرابط الخاص يعرض رفع الملفات وحفظ النص المقروء، ثم يفتح طلب التوليد في ChatGPT. تعود الكويزات المحفوظة إلى مساحة الحل والمراجعة والمحاولات الجديدة والحذف. واجهة المتصفح تنتظر نجاح الخادم قبل إعلان حفظ المصدر أو الإجابة؛ ولا تعلن اكتمال الكويز قبل إنشائه فعلًا.

**حد الجودة:** نص الصفحة والاقتباس كلاهما يقدمهما نموذج المحادثة، لذا التحقق هنا يثبت اتساقهما الداخلي فقط، وليس استخراجًا مستقلاً من الملف. الحالة الداخلية `model_generated_source_quote_checked` لا تعني مراجعة بشرية. يجب تجربة ملفات طلاب حقيقية بمراجعة مستقلة قبل الادعاء بجودة مثبتة. لا توجد بطاقات مراجعة أو PDF في مسار ChatGPT هذا؛ تبقى هذه الميزات في مسارات المنتج الأخرى وفق حالتها الخاصة.

## تشغيل وفحص الكود

يتطلب Node.js 22 أو أحدث، ولا توجد اعتماديات npm خارجية:

```bash
cd chatgpt-app
npm test
npm run build
npm run check:artifact
node scripts/preview.mjs --demo # معاينة محلية ببيانات اختبار واضحة، على 127.0.0.1:4174
```

الاختبارات الإحدى عشرة تحاكي التخزين وهوية طالبين ورفض الدليل المختلق والمفتاح الخاطئ والتكرار، وتتحقق من حجب الإجابات في الاختبار والأسئلة غير المجابة في التدريب، وAPI المتصفح من حفظ المصدر إلى إنشاء الكويز وحذفه، وتحميل القوائم من الملخصات، وعقد الواجهة المضمّنة وإرسال الصفحات المختارة إلى النموذج. فُحص رفع PDF نصي محليًا في صفحة Site؛ نجح حفظ المصدر وظهر رابط الطلب، ولم يُثبت أن رابط المحادثة استدعى التطبيق أو ولّد الكويز بحساب حقيقي. لا تعوّض هذه الاختبارات تدقيق جودة أسئلة ملف طالب حقيقي.

ملف `.openai/hosting.json` يحوي معرّف Site الحالي و`mcp` و`r2: "BUCKET"`. مصدر النسخة الخاصة محفوظ أيضًا في مستودع Sites منفصل؛ أي تعديل هنا يحتاج مزامنة ذلك المستودع، بناء `dist/server/index.js`، دفع الالتزام المطابق، ثم نشر نسخة Sites جديدة. موقع GitHub Pages لا يتغير بمجرد تغيير هذا المجلد.

## حدود تشغيل مهمة

- المالك لا يدفع استدعاء API عبر هذا الكود، لكن استخدام الطالب محكوم بإمكانات وحدود حساب ChatGPT وخطة توزيع التطبيق، ولا يوجد ضمان بأن كل الحسابات أو كل الملفات مدعومة.
- Site الخاص لا يتيح الوصول لطلاب آخرين الآن؛ إثبات الفصل بين مستخدمين أجري محليًا بمحاكاة هويتيهما فقط.
- تخزين R2 الحالي يحفظ كويزًا كاملًا في كائن واحد وملخصًا صغيرًا في بياناته الوصفية لتسريع القائمة. يوجد حذف ذاتي، لكن لا توجد معاملات متزامنة أو تصدير بيانات بعد. لا توسّع الاستخدام العام قبل معالجة التزامن وإدارة البيانات.
- لا يوجد ضمان إنجاز كويز خلال 15 ثانية؛ الزمن يتبع قراءة الملف وتوليد النموذج وحدود خطته.
