# كويزي داخل ChatGPT — نسخة خاصة قابلة للتجربة

هذا تطبيق منفصل داخل ChatGPT مبني على Sites MCP. يرفع الطالب ملف PDF أو PPTX في المحادثة، ويقرأه نموذج ChatGPT المتاح لحسابه، ويُعدّ نص الصفحات والأسئلة. أدوات كويزي تحفظ الأسئلة والإجابات وتعرضها لاحقًا. لا يستدعي كود التطبيق OpenAI API ولا يحتاج مفتاحًا من مالك كويزي. **هذه الآلية داخل ChatGPT فقط**؛ لا تفعّل التوليد بنموذج ChatGPT في موقع GitHub Pages المستقل.

**تصحيح النطاق:** يريد صاحب المشروع تطبيق كويزي مضمّنًا داخل chatgpt.com، ينشئ الكويز ويعرض حله داخل واجهة التطبيق، دون تحويله إلى محادثة عامة. أدوات MCP والحفظ تعمل، لكن واجهة التوليد المضمّنة لم تُنفّذ أو تُختبر بعد؛ مساحة الويب الخاصة الحالية ليست تلك الواجهة. أزيل زر التحويل إلى المحادثة منها، وصار يشير إلى موقع كويزي الأساسي ومولّده المحلي الحالي. مسار [CHATGPT-CONNECTION.md](../docs/CHATGPT-CONNECTION.md) يخص موقعًا مستقلًا يستخدم حصة ChatGPT، وهو خيار تقني مختلف.

الرابط الخاص الحالي: <https://quizzy-chatgpt-study.sasfas18.chatgpt.site>. التطبيق مملوك لصاحب المشروع ومثبت له حاليًا؛ إتاحته للطلاب من حساباتهم تتطلب نشرًا/مراجعة وتوزيعًا مناسبًا للتطبيق، ولا يكفي نشر الرابط وحده.

## المسار المنفذ

1. يرفع الطالب ملفه داخل محادثة ChatGPT ويطلب كويزًا باستخدام تطبيق كويزي.
2. يستخرج النموذج النص المقروء مع أرقام الصفحات، ثم يرسل دفعة أسئلة إلى `create_quiz_from_slides`. للعدد الكبير تُستخدم `add_quiz_questions` حتى 100 سؤال، على دفعات لا تتجاوز 30.
3. تفحص الأداة شكل الأسئلة، تطابق اقتباس الدليل مع نص الصفحة المرسل، تفرد الخيارات والمفتاح، وتكرار نص السؤال والغرض. لا تُفرض الهوية العشرة إذا لم يدعمها المصدر؛ تعاد الأقسام الناقصة صراحةً.
4. تحفظ البيانات في R2 ضمن مفتاح مبني على معرّف مستخدم ChatGPT الذي تقدمه Sites. أدوات MCP تعرض الكويزات والأسئلة، تحفظ الإجابات، وتراجع الأخطاء. التدريب يصحح فورًا، والاختبار يحجب المفتاح حتى اكتمال الإجابات.
5. الرابط الخاص يعرض مساحة تجريبية للكويزات والحل والمراجعة والمحاولات الجديدة والحذف. واجهة المتصفح تستدعي API على نفس Site، وتنتظر نجاح الخادم قبل إعلان الحفظ. تظل صناعة الأسئلة لهذا النموذج التجريبي داخل محادثة ChatGPT؛ زر الواجهة يشير الآن إلى موقع كويزي الأساسي ولا يعد بتوليد ChatGPT داخله.

**حد الجودة:** نص الصفحة والاقتباس كلاهما يقدمهما نموذج المحادثة، لذا التحقق هنا يثبت اتساقهما الداخلي فقط، وليس استخراجًا مستقلاً من الملف. الحالة الداخلية `model_generated_source_quote_checked` لا تعني مراجعة بشرية. يجب تجربة ملفات طلاب حقيقية بمراجعة مستقلة قبل الادعاء بجودة مثبتة. لا توجد بطاقات مراجعة أو PDF في مسار ChatGPT هذا؛ تبقى هذه الميزات في مسارات المنتج الأخرى وفق حالتها الخاصة.

## تشغيل وفحص الكود

يتطلب Node.js 22 أو أحدث، ولا توجد اعتماديات npm خارجية:

```bash
cd chatgpt-app
npm test
npm run build
npm run check:artifact
node scripts/preview.mjs --demo # معاينة محلية ببيانات اختبار واضحة، على 127.0.0.1:4174
```

الاختبارات السبعة تحاكي التخزين وهوية طالبين ورفض الدليل المختلق والمفتاح الخاطئ والتكرار، وتتحقق من حجب الإجابات في الاختبار والأسئلة غير المجابة في التدريب، وAPI المتصفح من الإنشاء إلى الحذف، وتحميل قائمة الكويزات من الملخصات دون إعادة قراءة نصوص الملفات. فُحصت الواجهة بصريًا على عرض الحاسوب والجوال، مع إجابة خاطئة ومراجعتها. لا تعوّض هذه الاختبارات تدقيق جودة أسئلة ملف طالب حقيقي.

ملف `.openai/hosting.json` يحوي معرّف Site الحالي و`mcp` و`r2: "BUCKET"`. مصدر النسخة الخاصة محفوظ أيضًا في مستودع Sites منفصل؛ أي تعديل هنا يحتاج مزامنة ذلك المستودع، بناء `dist/server/index.js`، دفع الالتزام المطابق، ثم نشر نسخة Sites جديدة. موقع GitHub Pages لا يتغير بمجرد تغيير هذا المجلد.

## حدود تشغيل مهمة

- المالك لا يدفع استدعاء API عبر هذا الكود، لكن استخدام الطالب محكوم بإمكانات وحدود حساب ChatGPT وخطة توزيع التطبيق، ولا يوجد ضمان بأن كل الحسابات أو كل الملفات مدعومة.
- Site الخاص لا يتيح الوصول لطلاب آخرين الآن؛ إثبات الفصل بين مستخدمين أجري محليًا بمحاكاة هويتيهما فقط.
- تخزين R2 الحالي يحفظ كويزًا كاملًا في كائن واحد وملخصًا صغيرًا في بياناته الوصفية لتسريع القائمة. يوجد حذف ذاتي، لكن لا توجد معاملات متزامنة أو تصدير بيانات بعد. لا توسّع الاستخدام العام قبل معالجة التزامن وإدارة البيانات.
- لا يوجد ضمان إنجاز كويز خلال 15 ثانية؛ الزمن يتبع قراءة الملف وتوليد النموذج وحدود خطته.
